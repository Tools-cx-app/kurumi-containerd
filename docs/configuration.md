## File location and container selection

CLI and TUI read `$HOME/.kurumi-containerd/config.json`. `HOME` must be absolute
and belongs to the running process; `sudo -H` normally selects root's HOME.
Create the file yourself. Missing files, invalid JSON, unknown fields and invalid
values produce errors without fallback or automatic configuration creation.

The top level is a nonempty list of complete configuration objects:

```json
[
  {
    "runtime": {},
    "container": {
      "name": "debian",
      "rootfs": "/srv/kurumi/debian/rootfs"
    }
  }
]
```

Each object requires `runtime` and `container`. Names are unique and
case-sensitive. A sole entry is selected automatically; with multiple entries,
put `--name NAME` before the command. `backup CONTAINER_ID OUTPUT` instead uses
its positional ID as `container.name` and rejects `--name`. The TUI lists all
entries. `check` does not read HOME or configuration.

There are no outer `name`/`file` pointers, standalone TOML loading,
`-c/--config`, or `KURUMI_CONTAINERD_CONFIG`. See the
[migration guide](migration-config-pointer.md) for older installations.

## Paths and persistent identity

Relative host paths resolve from the directory containing `config.json`:
`rootfs`, `rootfs_image`, bind-mount `source`, and `environment_file`.
Paths do not expand `~` or environment variables. `init` and mount `target`
refer to paths inside the container, even when they begin with `/`.

Normal runtime commands persist a missing UUID in the selected entry. The
atomic rewrite preserves other entries, ownership, permissions and a symlink
to the configuration file. Existing UUIDs remain unchanged. Installation,
backup and read-only TUI refresh do not persist missing UUIDs. Back up this
JSON separately from rootfs archives.

## Runtime settings

| Field in `runtime` | Default | Meaning and validation |
| --- | --- | --- |
| `stop_timeout_seconds` | `15` | Graceful-shutdown timeout in seconds; must be greater than zero |

Runtime files live in `/run/kurumi-containerd` on Linux and
`$TMP/kurumi-containerd` on Android. The directory must be root-owned, must not
be group/world writable, and must not be a symlink. There is no configurable
work-directory field.

## Container settings

| Field in `container` | Default | Meaning and validation |
| --- | --- | --- |
| `name` | Required | ASCII letters, digits, `.`, `_`, `-`; nonempty, excluding `.` and `..` |
| `uuid` | Absent | Persistent UUID; generated by normal runtime loading when missing |
| `rootfs` | Absent | Host directory; configure exactly one of this and `rootfs_image` |
| `rootfs_image` | Absent | Host filesystem image or block-device path |
| `hostname` | Container name | Empty or omitted values use `name` |
| `init` | `/sbin/init` | Absolute path inside rootfs |
| `foreground` | `false` | Connect start/restart to a foreground console |
| `volatile` | `false` | Put writable OverlayFS layers on tmpfs; changes are discarded |
| `network` | `host` | `host`, `none`, `nat`, `gateway`, or `dhcp` |
| `network_options` | Defaults below | Network addresses, bridge, DNS and port forwarding |
| `resources` | No configured limits | cgroup limits described below |
| `security` | Defaults below | Kernel views and nested user namespaces |
| `environment` | `{}` | String-valued environment assignments |
| `environment_file` | Absent | Host environment-file path |
| `mounts` | `[]` | Bind mounts described below |
| `android` | All flags `false` | Android host integration described below |

Normal loading requires an existing rootfs and, for directory roots, the
configured init path. `install` allows a missing target: it installs a local
archive into `rootfs`, or creates a sparse ext4 `rootfs_image` with `--size SIZE`.
Existing targets require `--force`. See [installation](usage.md#install-a-local-rootfs).

The following examples are object fragments to merge into the selected entry,
not complete configuration files. [config.example.json](../config.example.json)
provides a larger example; adapt its paths and remove mounts you do not need.

## Networking

| Mode | Behavior |
| --- | --- |
| `host` | Share host networking |
| `none` | Use an isolated network namespace |
| `nat` | Configure a private network with host NAT and optional port forwarding |
| `gateway` | Attach a veth to the existing `gateway_bridge` with static addressing |
| `dhcp` | Attach to the existing `gateway_bridge` and run a DHCP client inside rootfs |

```json
{
  "container": {
    "network": "nat",
    "network_options": {
      "address": "172.28.0.2",
      "gateway": "172.28.0.1",
      "prefix": 16,
      "bridge": "kurumi-br0",
      "gateway_bridge": "",
      "dns": ["1.1.1.1", "8.8.8.8"],
      "ports": [{"host": 8080, "container": 80, "protocol": "tcp"}]
    }
  }
}
```

The addresses, prefix, bridge names and DNS above are the defaults; `ports`
defaults to an empty list. `address` and `gateway` are IPv4 addresses; DNS entries
must be IP addresses. Prefix must be at most 32. Each forwarding rule requires
nonzero `host` and `container` ports in the 16-bit range; `protocol` is `tcp`
(default) or `udp`. Within one protocol, duplicate host ports or duplicate
container ports are rejected. Port ranges are unsupported.

NAT and bridge setup use host `ip` and `iptables` executables. `gateway` and
`dhcp` require a valid `gateway_bridge` naming an existing bridge; the runtime
does not create or manage that bridge. DHCP uses the first client found inside
rootfs: `udhcpc`, `dhclient`, then `dhcpcd`.

```json
{
  "container": {
    "network": "dhcp",
    "network_options": {"gateway_bridge": "br0"}
  }
}
```

Changes to networking or resource settings apply on the next start. `enter`
and `run` join the running container's actual namespaces and cgroups.

## Resource limits and security

```json
{
  "container": {
    "resources": {
      "memory_bytes": 536870912,
      "cpu_quota": 100000,
      "cpu_period": 100000,
      "pids": 512
    },
    "security": {
      "read_only_sys": true,
      "allow_user_namespaces": false
    }
  }
}
```

Resource fields are optional unsigned integers. Limits use cgroup v2 when
available, otherwise cgroup v1. `memory_bytes` must be at least 4194304 (4 MiB).
CPU quota and period are in microseconds and must be supplied together;
`cpu_quota` must be at least 1000 and `cpu_period` greater than zero.
`pids` must be between 1 and 4194304. Unavailable requested controllers are
reported as errors.

`read_only_sys` defaults to `true`; `allow_user_namespaces` defaults to `false`.
Enable the latter only for trusted workloads needing unprivileged user
namespaces, such as Docker userns-remap, Podman, Flatpak or Bubblewrap. The
normal hardened `/proc` and `/sys` remain, alongside fresh mounts at
`/run/kurumi-containerd/proc` (writable) and `/run/kurumi-containerd/sys`
(read-only). The extra proc view can expose host kernel sysctls and weakens
isolation. Container root retains capabilities; this is not a hostile-workload
security boundary.

## Environment and bind mounts

```json
{
  "container": {
    "environment_file": "./container.env",
    "environment": {"LANG": "C.UTF-8"},
    "mounts": [
      {"source": "./shared", "target": "/mnt/shared", "read_only": false}
    ]
  }
}
```

Environment files accept `KEY=VALUE`, optional `export`, comments, quoted and
empty values, and values containing `=`. Inline assignments override file
assignments. Keys must be valid environment-variable names and values cannot
contain NUL bytes. The environment file must exist.

Each mount requires an existing host `source` and an absolute, non-root container
`target` without parent traversal. `read_only` defaults to `false`. Bind mounts
expose host data to the container; rootfs backup does not include their sources.

## Android integration

All fields in `container.android` are booleans defaulting to `false`:

| Field | Host resource or effect |
| --- | --- |
| `storage` | Bind `/storage/emulated/0` into the container |
| `gpu` | Expose matching DRI render, KGSL, Mali and video devices |
| `binder` | Expose `/dev/binder`, `/dev/hwbinder` and `/dev/vndbinder` |
| `termux_x11` | Bind the Termux X11 `X5` socket to `/tmp/.X11-unix/X5` |
| `virgl` | Bind Termux's `.virgl_test` socket to `/tmp/.virgl_test` |
| `pulse_audio` | Bind Termux's `.pulse-socket` to `/tmp/.pulse-socket` |
| `selinux_permissive` | Request permissive SELinux handling for the container lifetime |

These options require an Android build and suitable host resources; unsupported
hosts or missing requested resources produce errors. They expose resources and
do not install or supervise Android applications or the corresponding host
services. See [Android root module](android-module.md) for installation and
boot startup.
