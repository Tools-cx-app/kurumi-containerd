# 实现状态

[[zh](status_CN.md) / [en](status.md)]

[文档目录](README_CN.md)

KurumiContainerd 是处于早期阶段的 Rust 实现，用于需要特权的 Linux 和 Android 系统容器。
核心生命周期已经可用，但在依赖它之前，应先在可丢弃的系统上评估。它共享宿主内核，要求
使用可信的 rootfs 和命令。

## 已实现

### 生命周期与检查

- 启动、停止与重启，支持前台 PTY 控制台和后台监控
- 根据 init 类型执行优雅关机、超时升级终止，以及容器内部重启代次管理
- 交互式 `enter` 和非交互式 `run`，并传递命令退出状态
- 通过描述符传递实现控制台与交互会话
- init PID、详细信息、存活容器列表、宿主能力检查，以及经过验证的恢复扫描
- 持久 UUID；通过宿主启动 ID、进程启动时间和 PID 命名空间 inode 校验进程身份，
  防止误认被复用的 PID

### 文件系统、安装与备份

- 目录、ext4 镜像、btrfs 镜像和块设备 rootfs 模式，绑定挂载，以及易失性 OverlayFS
- 将本地 tar、gzip tar、XZ tar、Zstandard tar 或 ZIP rootfs 归档安装到目录或稀疏
  ext4 镜像；通过文件头检测格式
- 使用暂存安装并在替换前验证 init；替换现有目标需要 `--force`，且容器必须处于停止状态
- 通过 CLI 和可选 TUI 为停止的容器备份 rootfs，支持 `.zst`、`.xz`、`.zip` 或 `.tar`，
  导出期间持有生命周期锁
- 备份流式写入权限为 `0600` 的私有临时文件，只在成功后发布，不覆盖现有路径或符号链接

备份导出的是 rootfs 内容，而非原始磁盘镜像或完整容器包。容器选择规则、元数据保留范围、
排除项和恢复限制见[备份与恢复说明](usage_CN.md)。

### 隔离与宿主集成

- 挂载、UTS、IPC、PID，以及可选的网络命名空间
- 宿主网络、隔离网络、NAT 和现有网桥网络
- TCP/UDP 单端口转发，支持回滚并清理由本工具持有的规则
- cgroup v1/v2 内存、CPU 和 PID 数量限制
- 命令进入运行中容器实际使用的命名空间与 cgroup，不受启动后修改配置的影响
- classic-BPF seccomp 过滤、sys/proc 只读控制和绑定遮罩
- 为嵌套用户命名空间沙箱提供可选的未遮罩 proc/sysfs 挂载
- 运行时提供可选 Android 存储、设备和 socket 集成
- 支持容器开机启动的 Magisk、KernelSU 和 APatch root 模块，参见
  [Android 模块指南](android-module_CN.md)

### 可选终端管理器

`tui` Cargo feature 默认关闭。启用后，ratatui 管理器会读取 HOME 下的 JSON 注册表，
显示包括已停止容器在内的配置条目，刷新运行时状态，并通过同一个 CLI 可执行文件分派操作。
它提供安装、备份、生命周期操作、进入容器、执行命令、信息检查、扫描恢复和宿主检查。
未启用该 feature 的构建没有 `tui` 子命令；面向整个工作区的构建仍包含 TUI crate。

## 当前限制

### 安全与恢复

- 不削减容器 root 的 capabilities。seccomp 和受保护的内核视图并不构成面向恶意工作负载的
  安全边界。
- 启用嵌套用户命名空间会增加未遮罩的可写 proc 视图，可能暴露宿主内核 sysctl，降低隔离
  强度。仅对可信容器使用。
- 恢复要求受保护的宿主恢复记录与匹配的容器内身份标记。仅发现一个进程或数值 PID
  不能建立信任。
- 某些宿主全局资源的崩溃后协调和清理仍不完整。

### 宿主与交互要求

- 网络依赖宿主的 `ip` 和 `iptables`；尚未实现端口范围和自动上游监测。
- 交互会话不支持脱离后重新连接。
- TUI 的交互和前台操作要求 Linux 上存在受支持的图形终端（`xterm`、`kitty` 或
  `alacritty`）。这些操作在无图形环境的 Linux 和 Android 上不可用；如果构建了 TUI，
  非交互管理仍然可用。
- TUI 最多捕获合并 stdout/stderr 的前 1 MiB。`run` 使用独立的可执行文件和参数字段，
  不解析 shell 语法。
- 后台监控进程在启动后将标准流重定向到 `/dev/null`；这不提供后台容器的持久日志功能。
- 命名空间、挂载、cgroup 和镜像操作需要相应权限与内核支持。镜像安装还需要 loop 设备，
  以及 `mke2fs` 或 `mkfs.ext4`；镜像安装必须指定 `--size`，目录安装则拒绝该参数。

### 归档与元数据限制

- 安装只接受本地归档，不支持 rootfs 下载或从注册表/URL 安装。归档必须将 init 放在
  rootfs 顶层对应的位置，不能在外面多包一层发行版目录。
- 备份要求 root 权限且容器已停止，不包含 config.json、运行时状态、绑定挂载的源目录，
  以及已丢弃的易失性 OverlayFS 改动。请单独保存配置，导出期间避免外部写入。
- 备份输出目录必须事先存在并位于 rootfs 之外。必须先卸载 rootfs 下已挂载的子树；
  内核文件系统和特殊文件（设备、socket、FIFO）会被拒绝，不会静默跳过。镜像源需要
  loop 设备和挂载支持。
- tar 备份保留所有权、权限、时间戳、硬链接、符号链接和 xattr。ZIP 备份会丢失所有权、
  时间戳、xattr、特殊权限位和硬链接身份；它保留普通权限和安全的相对符号链接，但拒绝
  绝对路径/越界符号链接，以及非 UTF-8 或有歧义的路径。ZIP 安装无法可靠保留 UID/GID
  或设备节点。系统 rootfs 归档应优先使用 tar 或压缩 tar。
- 当前安装器仅为普通文件恢复 tar xattr，PAX 读取器无法恢复包含换行的属性值。目录和
  符号链接的 xattr，以及含换行的属性值，需要借助启用了 xattr 恢复的外部 tar 实现。

### 平台与接口成熟度

- Android 服务监督和完整硬件/设备策略仍不完善。
- 尚无 Android 应用、守护进程/客户端 API、通用软件包安装器，或稳定的机器可读输出约定。
  上文所述的本地 rootfs 归档安装已经可用。

配置字段只有存在实际运行时处理路径时才会写入文档。失败应作为错误处理，不要假设系统会
降级回退。资源归属与信任规则见[架构说明](architecture_CN.md)，操作要求见
[CLI 用法](usage_CN.md)。
